# Typed Maru to Native Code Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** compile typed Maru (`ir2`) to arm64 and x86-64 machine code in-process, through architecture-neutral intents, so every ir2 program and then the Nile runtime and Gezira run without `cc`.

**Architecture:** a generator (`native-gen.k`) implements the protocol `maru.k`'s `compile-namespace` drives (`ir-gen-header`, `-preamble`, `-global-declaration`, `-function-implementation`, `-initialisation`, `-postamble`, `-declare-struct`) and lowers each ir2 instruction to intents on ir2's own frame slots (`ir-frame-allocate`, `ir-frame-finalise`, as `ir-gen-x86.k` uses them). Per-architecture tree-matching grammars (`native-arm64.g`, `native-x64.g`) lower intents to forms `asm-coverage.spec` lists; `native-link.l` encodes them (RFC 0001's `asm`, `asm-patch`), places globals, resolves externs, and installs the unit in a code region or saves it as a code image file that any evaluator loads.

**Tech Stack:** typed Maru (`maru.k`, `ir2.k`) on `eval2`; tpeg grammars (`compile-tpeg.l`); RFC 0001's encoders and `code-region.l`; `abi.spec`; `exe.l`.

**Spec:** `doc/rfc/draft-ndn-maru-native-ir2-00.md`

## Global Constraints

- Intents are the boundary: `native-gen.k` names no register, mnemonic or calling convention [R-neutral]; a lowering grammar knows no ir2.
- Every form a lowering grammar produces is one `asm-coverage.spec` lists for that operation and type [R-checked-rows].
- Every value lives in its frame slot; registers are scratch only (`abi.spec`'s scratch list). No allocator.
- `ir-gen-c.k` is the reference: every native result is compared with the same unit through `ir-gen-c.k` and `cc`.
- arm64 runs here; x86-64 runs natively on `ndn.lan` (Rosetta only as a smoke test).
- No `nice`. Bounded runs: only the cases a task needs. `check/lines` entries with reasons for every line change.
- Don't change `ir2.k`, the encoders or `code-region.l`.

## Review Focus

- A call with more arguments than argument registers (stack-passed arguments, AAPCS64 and System V): the callee must read them. Test in Task 4.
- A variadic call on Apple arm64 (variadic arguments on the stack, not in registers): `printf` with mixed ints and doubles must print right. Test in Task 4.
- Branches past a short field's range (a long `while` body): the lowering must use the long form, not fail. Test in Task 2.
- Sub-word loads and stores (`int8`, `int16`, `int32`), signed and unsigned: sign and zero extension must match C. Test in Task 3.
- A function called from untyped Maru with `subr` after loading a code image under another evaluator (`eval` loading what `eval2` compiled): the same result. Test in Task 6.
