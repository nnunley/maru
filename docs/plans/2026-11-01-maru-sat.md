# SAT Solver for Maru — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Maru gains a CDCL SAT solver written in irl, whose unsatisfiable answers carry
DRAT proofs a separate checker verifies, and JOHN's `satisfy` gains a SAT planner that
bit-blasts programs with names, numbers and lists.

**Architecture:**
- **Typed code.** Three irl files, the DIMACS reader, the solver and the checker, compile
  together through `compile-irl.l`'s new library mode and ir2's C backend into `sat.dylib`.
- **The wrapper.** Untyped `sat.l` loads the library by absolute path, wraps the IPASIR
  calls, and checks every answer: models in Maru, proofs through the checker.
- **Clauses.** `cnf.l` builds clauses from gates, bit vectors and lists.
- **The JOHN encoder.** `john-sat.l` uses it to encode a JOHN program as a bounded model, and
  `john-eval.l`'s `satisfy` calls it under `set-opt planner sat`.

**Tech Stack:**
- typed: irl (`irl.g`, `compile-irl.l`) → `maru.k`/ir2 → `ir-gen-c.k` → `cc -shared`;
- untyped: Maru (`eval`), `subr`/`dlopen`/`dlsym`;
- checks: `check/check.l`, run through `make check CHECKS=…`.

**Spec:** `docs/rfc/draft-ndn-maru-sat-00.md`. JOHN's semantics: `john-eval.l` and
`~/pkm/wiki/synthesis/john-language-reconstruction.md`.

## Global Constraints

- **The solver and the checker are irl, never hand-written C.** They may `import` libc
  functions (`malloc`, `realloc`, `free`, `fopen`, `fputs`, `fgets`, `fclose`), as `test.irl`
  does.
- **The checker shares no code with the solver beyond reading literals.** `dimacs.irl` is the
  only file both use. [RFC: The checker is simpler than the solver]
- **IPASIR numbering:** `sat_solve` answers `10` (SAT), `20` (UNSAT) or `0` (UNKNOWN).
- **Defaults** (spec, Configuration): `planner search`, `sat-width 16`, `sat-list-length 16`,
  `sat-unroll 16`, `sat-proof-dir /tmp/maru-sat`, `sat-conflicts 1000000`. The plan length is
  bounded by `*john-limit*` (16).
- **Report lines, exactly:**
  - `trying K steps (V variables, C clauses): unsatisfiable`, or the same ending
    `satisfiable`;
  - then `satisfied at time: K` and `satisfied by: [ … ]`, in the search's format;
  - or `unsatisfiable within 16 steps (width 16, lists 16, unroll 16)`, with the values in
    force.
- **The time budget:** each `sat_*` check finishes within `run`'s 120 s ([R-time-budget]).
  Several agents share this machine, so long runs go under `nice`, and two `check/check.l`
  processes never run at once.
- **Run checks through make:** `make check CHECKS="NAME…"`, never `./eval check/check.l`
  directly.
- **Maru style:**
  - Dispatch on a value's type with `define-selector`/`define-method`, not `cond` chains or
    hand-written list helpers.
  - Define a function before any function that calls it; `eval` resolves free globals when a
    closure is made.
  - `concat-list` recurses once per element, so build long lists by `push` and
    `list-reverse!`.
- **Bookkeeping:**
  - Every change in line count gets a `check/lines` entry with its delta and reason.
  - Commits carry no attribution.
  - One worktree branch per task, fast-forwarded to `main` when its checks pass, then deleted.
- **Third-party data:** none in the tree. Every test formula is generated.

## Review Focus

1. **A variable in no clause** still has a value: `sat_val` answers for every variable up to
   the largest added. Tested in Task 2.
2. **An empty clause added directly** makes the formula UNSAT at once. Its proof is just `0`,
   and the checker accepts it. Tested in Task 3.
3. **A goal that already holds at time 0** is satisfied at time 0 with the plan `[ ]`, not
   after a first step. Tested in Task 6.
4. **The encoder writes tautologies or repeated literals** (`x ∨ ¬x`, `x ∨ x`). `sat-decide`
   drops tautologies and repeats before solving, and DIMACS files it writes never hold them.
   Tested in Task 4.
5. **The conflict limit is reached:** UNKNOWN is reported as `unknown at K steps (conflict
   limit N)`, never as unsatisfiable. Tested in Task 6 with `sat-conflicts 1` on a program
   needing search.

### Task 3: DRAT proofs and the forward checker [R-drat] [R-checker] [R-checker-rejects]

**Files:**
- Create: `drat-check.irl`, `check/sat-proof.l`
- Modify: `sat.irl`, `sat.l`, `check/check.l` (case `sat_proof`), `check/lines`

**Interfaces:**
- Consumes: Task 1's `dimacs_load` (the checker reads the formula itself) and Task 2's solver.
- Produces (C ABI):
  - `long sat_set_proof(void* s, char* path)`: returns 1 once the proof file is open. It
    applies to solves without assumptions on a fresh solver ([R-drat]).
  - `long drat_check(char* cnf_path, char* proof_path)`: 1 accepts, 0 rejects.
  - `long drat_failed_line()`: the proof line that failed, or 0.
- Produces (untyped):
  - `sat-decide` writes the formula as DIMACS and the proof under `sat-proof-dir`, naming both
    `<dir>/<n>.cnf` and `<dir>/<n>.drat`.
  - It checks every UNSAT answer, raising `E_PROOF: line L` otherwise.
  - The directory is created if missing, and refused if its last component is a symbolic link
    (`readlink` through `subr`: −1 means not a link).

- [ ] **Step 1: Write the failing check.** `check/sat-proof.l` asserts:
  - The pigeonhole formula, 3 pigeons in 2 holes (built inline), is UNSAT, and its proof is
    accepted.
  - A formula containing the empty clause gives a proof of just `0`, which is accepted
    (Review Focus 2).
  - Each mutant of a real proof is rejected:
    - the first non-trivial line dropped;
    - a literal negated in a learned clause;
    - the final `0` dropped;
    - an extra added clause `5 0` over a formula that doesn't imply it.
  - A proof dir that is a symbolic link is refused.
  - It prints `sat proof ok`.
- [ ] **Step 2:** Run `make check CHECKS=sat_proof`. Expected: FAIL.
- [ ] **Step 3:** Implement:
  - **Proof writing in `sat.irl`:** each learned clause as `lits 0`, each clause removed as
    `d lits 0`, and `0` at the end, written through `fputs` as they happen, not buffered whole.
  - **`drat-check.irl`, forward:**
    - Keep the formula's clauses, plus each added one once it passes.
    - A clause passes by RUP: assign its literals' negations, propagate, and look for a
      conflict.
    - Failing RUP, it passes by RAT on its first literal: check every clause containing that
      literal's negation, resolved with it.
    - Deletions remove a clause.
    - Accept when the empty clause passes.
- [ ] **Step 4:** Run `make check CHECKS="sat_proof sat_core lines"`. Expected: PASS.
- [ ] **Step 5:** Commit `sat: DRAT proofs for UNSAT answers, verified by a forward checker`.
