# STEPS budgeted 20,000 lines of meaning code for all of personal computing, and later counted optimisation too

The figure STEPS set was 20,000 lines of code for an entire personal computing system, from the end-user applications down to the metal. It was framed as a factor of ten below Squeak's roughly 200,000 lines. That figure appears in the 2006 proposal and is repeated in the 2007, 2008, 2010 and 2011 reports. No report gives a 10,000-line target; the places "10,000" appears describe other things (TCP/IP stacks in C, a browser, a document editor).

The budget was for "meaning code", the code that says what the system does. At first, optimisation code was excluded on the grounds that the meaning could run slowly on a supercomputer. By 2011 the project decided to count optimisations too, because it wanted real-time performance on a laptop. No report ever presents a summed total against the budget. The final report's own table counts 10,055 "essential" lines for the user-interface stack alone, with Maru's 4,317-line basis and the Nile chain counted separately.

Anyone citing a STEPS budget should therefore say 20,000. A 10,000-line budget is a stricter target of one's own, not VPRI's.

Source: Kay et al. 2006, STEPS NSF proposal (VPRI RN-2006-002), pp. 1, 13 (primary); STEPS reports 2007–2012 (TR-2007-008 p. 5; TR-2010-004 pp. 3–4; TR-2011-004 pp. 3, 5–6; TR-2012-001 pp. 4, 11, 32); full-text search of all seven reports, 2026-10-14.
